## 1. สถาปัตยกรรมซอฟต์แวร์และภาษาโปรแกรม

### 1.1 Flutter Framework
*   **คำอธิบาย:** Flutter เป็น Open-source UI Software Development Kit ที่พัฒนาโดย Google สำหรับสร้างแอปพลิเคชันแบบ Cross-Platform (Android และ iOS) จากฐานโค้ดชุดเดียวกัน (Single Codebase)
*   **หลักการทำงาน:** Flutter ใช้เอนจินการเรนเดอร์กราฟิกของตัวเอง (Impeller / Skia) ทำให้สามารถวาด UI ได้ด้วยความเร็ว 60-120 FPS ระดับเดียวกับ Native Application
*   **ประโยชน์ในโปรเจกต์:** ช่วยให้การพัฒนาแอปฉุกเฉินบนสมาร์ตโฟนมีความลื่นไหล มี UI ที่ตอบสนองทันทีในภาวะวิกฤต และเข้าถึงฮาร์ดแวร์ของระบบปฏิบัติการได้อย่างสมบูรณ์

### 1.2 ภาษา Dart (v3.10.4+)
*   **คำอธิบาย:** ภาษาโปรแกรมแบบ Strongly-Typed, Object-Oriented Programming (OOP) ที่พัฒนาโดย Google เป็นภาษาหลักที่ใช้ในการเขียน Flutter
*   **แนวคิดสำคัญ:** 
    *   **Sound Null Safety:** ป้องกันการเกิด Null Reference Error (NullPointerExceptions) ในระหว่างรันไทม์ ทำให้แอปไม่เด้งดับในสถานการณ์ฉุกเฉิน
    *   **Asynchronous Programming (`Future` และ `Stream`):** จัดการการประมวลผลพื้นหลัง เช่น การดึงพิกัด GPS, การรับส่งแพ็กเกจบลูทูธ และการอ่านไฟล์แคช โดยไม่ทำให้ UI ค้าง

### 1.3 สถาปัตยกรรม Offline-First Architecture
*   **หลักการ:** ออกแบบซอฟต์แวร์โดยสมมติฐานว่า **"ผู้ใช้ไม่มีสัญญาณอินเทอร์เน็ตอยู่ตลอดเวลา"** (Off-Grid Mode)
*   **การทำงาน:** แอปจะใช้อุปกรณ์ในตัวเครื่อง (Local Storage, SQLite, SharedPreferences) เป็นแหล่งข้อมูลหลักในการทำงาน และเมื่อเครื่องสามารถเชื่อมต่ออินเทอร์เน็ตได้ แอปจะทำการซิงโครไนซ์ข้อมูลแบบเบื้องหลัง (Background Sync)

### 1.4 รูปแบบการจัดสภาวะแวดล้อมและเลเยอร์ (State Management & Service Pattern)
*   **Provider Pattern:** ใช้ไลบรารี `provider` ในการจัดการ State ของแอปแบบ Reactive ช่วยลดการยึดติดกันของโค้ด (Decoupling)
*   **Service & Repository Pattern:** แยกส่วนการทำงานออกเป็น Service เฉพาะทาง เช่น `NearbyService`, `WeatherService`, `CryptoMeshService`, `FirstAidService` เพื่อให้อ่านง่าย ทดสอบง่าย และดูแลรักษาสะดวก

## 2. ระบบเครือข่ายและการสื่อสารไร้เซิร์ฟเวอร์

### 2.1 ทฤษฎี Peer-to-Peer (P2P) Mesh Networking
*   **แนวคิด:** การสื่อสารที่อุปกรณ์แต่ละเครื่อง (Node) เชื่อมต่อถึงกันโดยตรงโดยไม่ต้องพึ่งพาเซิร์ฟเวอร์กลาง (Decentralized Network)
*   **การส่งต่อข้อความ (Multi-hop Relay):** โหนดที่รับข้อความจะทำหน้าที่ส่งต่อข้อความไปยังโหนดถัดไปในระยะ ทำให้ครอบคลุมพื้นที่สัญญาณได้ไกลกว่าระยะบลูทูธปกติ

### 2.2 Google Nearby Connections API
*   **คำอธิบาย:** API ระดับระบบปฏิบัติการที่ช่วยให้อุปกรณ์ Android/iOS ในบริเวณใกล้เคียงค้นพบ (Discovery) และเชื่อมต่อ (Connection) ถึงกันโดยไม่ต้องใช้อินเทอร์เน็ต
*   **โหมดการเชื่อมต่อที่ใช้:** `Strategy.P2P_CLUSTER` (Topology แบบใยแมงมุมที่ทุกเครื่องค้นหาและเชื่อมต่อกันได้อย่างอิสระ)
*   **เทคโนโลยีสื่อสารไร้สายย่อย:**
    1.  **Bluetooth Low Energy (BLE):** ใช้พลังงานต่ำมากในการกระจายสัญญาณคายตัวตน (Advertising & Discovery)
    2.  **Wi-Fi Direct & Wi-Fi SoftAP:** สลับช่องทางเป็น Wi-Fi ความเร็วสูงโดยอัตโนมัติเมื่อมีการรับส่งข้อมูลขนาดใหญ่หรือส่งข้อความต่อเนื่อง

## 3. ทฤษฎีความปลอดภัยและการเข้ารหัสลับ

### 3.1 End-to-End Encryption (E2EE)
*   **แนวคิด:** การเข้ารหัสข้อมูลที่ต้นทาง (Sender) และให้ถอดรหัสได้ที่ปลายทาง (Recipient) เท่านั้น โดยที่อุปกรณ์ตัวกลางที่ทำหน้าที่กระจายสัญญาณ Mesh ไม่สามารถอ่านเนื้อหาข้างในได้

### 3.2 SHA-256 Cryptographic Hash Algorithm
*   **ฟังก์ชัน:** แปลงข้อมูลความยาวใดๆ ให้เป็นค่า Hash ขนาด 256-bit (32-byte) ที่ไม่สามารถย้อนกลับได้
*   **การประยุกต์ใช้:** ใช้สร้างคีย์รับส่งข้อมูลคู่เฉพาะ (Pairwise Master Key) โดยนำ ID ของผู้ส่งและผู้รับมาคำนวณผ่าน SHA-256 Key Derivation Function (KDF)

### 3.3 Symmetric Stream Cipher & Random IV
*   **กระบวนการเข้ารหัส (Encrypt V2):** 
    1. สุ่มค่า Initial Vector (IV) ขนาด 16-byte ด้วย `Random.secure()`
    2. นำข้อความใส (Plaintext) มา XOR กับคีย์ที่ผันแปรตาม IV และตำแหน่ง Byte
    3. แปลงผลลัพธ์เป็น Base64
*   **ข้อดี:** ประมวลผลได้รวดเร็วมากบนสมาร์ตโฟน กินพลังงานซีพียูต่ำ เหมาะสำหรับการสื่อสารผ่านบลูทูธ

### 3.4 HMAC-SHA256 (Hash-based Message Authentication Code)
*   **แนวคิด:** การรับประกันความถูกต้องของข้อมูล (Integrity & Anti-Tampering Check)
*   **การทำงาน:** แนบ รหัส MAC ที่คำนวณจากคีย์และความลับไปด้วย หากข้อความถูกดัดแปลงระหว่างทางจากอุปกรณ์ Node อื่น รหัส MAC จะไม่ตรงกัน และระบบจะปฏิเสธข้อความนั้นทันที

## 4. ระบบสารสนเทศภูมิศาสตร์และการนำทาง

### 4.1 ระบบพิกัดภูมิศาสตร์ WGS84
*   **มาตรฐาน:** World Geodetic System 1984 ซึ่งเป็นพิกัดอ้างอิงของระบบดาวเทียมระบุตำแหน่งโลก (GPS)
*   **รูปแบบข้อมูล:** ใช้ค่าละติจูด (Latitude: -90 ถึง +90) และลองจิจูด (Longitude: -180 ถึง +180) ในการระบุจุดบนผิวโลก

### 4.2 OSM Tile Grid Standard (XYZ Raster Tiles)
*   **หลักการ:** แบ่งภาพแผนที่โลกออกเป็นแผ่นสี่เหลี่ยม (Tiles) ขนาด 256x256 พิกเซล ตามระดับการซูม (Zoom Level 0–19)
*   **สมการอ้างอิงพิกัด:** พิกัดบนแผนที่ดาวเทียมจะถูกแปลงเป็นตำแหน่ง $X, Y, Z$ เพื่อใช้จัดเก็บลงไฟล์แคช (Local Map Cache) ในตัวเครื่อง

### 4.3 OSRM Polyline Decoding
*   **แนวคิด:** การบีบอัดพิกัดเส้นทางนำทางหลายร้อยจุดให้อยู่ในรูปแบบสตริงข้อความสั้น (Encoded Polyline Algorithm)
*   **การนำไปใช้:** แอปจะถอดรหัสสตริงจาก OSRM Routing API ออกมาเป็นจุดพิกัด `List<LatLng>` แล้วนำไปวาดเส้นเรืองแสงบนแผนที่

## 5. บริการเว็บเอพีไอภายนอก

| ชื่อบริการ API | ประเภทข้อมูล | วัตถุประสงค์ในโปรเจกต์ |
| :--- | :--- | :--- |
| **Longdo Map API** | REST / Tile Server | ดึงตำแหน่งโรงพยาบาล (POI), รายงานเหตุการณ์จราจร/อุบัติเหตุ และเลเยอร์จราจรในประเทศไทย |
| **Overpass API (OSM)** | Overpass QL / JSON | ค้นหาพิกัดโรงพยาบาลและสถานพยาบาลฉุกเฉินนอกเขตประเทศไทยหรือพื้นที่ที่ขาดสัญญาณ Longdo |
| **OSRM Routing API** | REST API | คำนวณเส้นทางนำทางเลี้ยวต่อเลี้ยว (Turn-by-turn driving route) ระหว่างตำแหน่งผู้ใช้และสถานพยาบาล |
| **Open-Meteo Weather API** | REST API | ตรวจสอบอุณหภูมิ สภาพอากาศ และประเมินความเสี่ยงภัยพิบัติทางธรรมชาติ |
| **Open-Meteo Air Quality API**| REST API | ดึงค่าฝุ่นละออง PM 2.5 และสารเคมีในบรรยากาศ (CO, NO2, O3) บริเวณรอบตัวผู้ใช้ |
| **Photon / Nominatim API** | Forward Geocoding | แปลงชื่อสถานที่ภาษาไทย (เช่น "หาดใหญ่") เป็นพิกัดละติจูด/ลองจิจูด เพื่อย้ายมุมกล้องแผนที่ |

## 6. การเชื่อมต่อเซนเซอร์และฮาร์ดแวร์อุปกรณ์

1.  **GPS/GNSS Receiver (`geolocator`):** เข้าถึงระบบดาวเทียมระบุตำแหน่งในตัวเครื่องเพื่อคำนวณพิกัดผู้ใช้ ความแม่นยำ และความเร็วเคลื่อนที่
2.  **Magnetometer Sensor (`flutter_compass`):** ตรวจรับค่าสนามแม่เหล็กโลก เพื่อทำหน้าที่เป็นเข็มทิศดิจิทัล (Digital Compass) แสดงทิศเหนือแม่เหล็ก (Magnetic North)
3.  **Flashlight / Camera LED Controller (`torch_light`):** ควบคุมหลอดไฟ Flash ของกล้องมือถือ กระพริบตามจังหวะรหัส Morse Code สัญญาณขอความช่วยเหลือ SOS (`... --- ...`)
4.  **Audio Player & Sound Synthesizer (`audioplayers`):** เล่นไฟล์เสียงไซเรนฉุกเฉินความถี่สูงเพื่อส่งสัญญาณเตือนภัยหรือระบุพิกัดให้ทีมกู้ภัยหาตัวเจอ
5.  **Text-To-Speech Engine (`flutter_tts`):** ระบบอ่านออกเสียงคำสั่งปฐมพยาบาลและคำเตือนฉุกเฉินภาษาไทยสำหรับผู้พิการทางสายตาหรือในสภาวะที่ไม่สามารถมองหน้าจอได้
6.  **Battery & System Health API (`battery_plus`):** อ่านระดับเปอร์เซ็นต์แบตเตอรี่และสถานะชาร์จ เพื่อปรับเข้าสู่โหมดประหยัดพลังงานฉุกเฉิน (Ultra Power Saving)

## 7. การออกแบบอินเทอร์เฟซและการแสดงผลข้อมูล

*   **Material Design 3 (M3):** ระบบการออกแบบ UI ยุคใหม่จาก Google เน้นความเข้าถึงง่าย (Accessibility) ปุ่มขนาดใหญ่กดง่ายในสถานการณ์ฉุกเฉิน
*   **Interactive Map Rendering (`flutter_map`):** ไลบรารีเรนเดอร์แผนที่ความเร็วสูง รองรับการวาดหมุดสถานที่ (Markers), เลเยอร์ความร้อน (Heatmaps) และเส้นทาง (Polylines)
*   **Data Visualization (`fl_chart`):** วาดกราฟเส้นและกราฟแท่งเพื่อแสดงแนวโน้มคุณภาพอากาศ PM 2.5 และอุณหภูมิย้อนหลัง/ล่วงหน้า
*   **High-Contrast Emergency Theme:** ธีมสีมืด (Dark Mode) คอนทราสต์สูง ใช้สีแดงฉุกเฉิน (#FF3B30) และสีเขียวความปลอดภัย (#34C759) ช่วยลดการใช้พลังงานของหน้าจอ OLED/AMOLED และมองเห็นได้ชัดเจนในมืด
