# บทที่ 5
# สรุปผลการวิจัย ข้อจำกัด และข้อเสนอแนะ (Conclusion, Limitations & Future Work)
## โครงงาน: ระบบสนับสนุนความปลอดภัยส่วนบุคคลบนสมาร์ตโฟน (BANTAWAN)

---

## 5.1 สรุปผลการดำเนินงาน (Conclusion)
โครงงาน **"ระบบสนับสนุนความปลอดภัยส่วนบุคคลบนสมาร์ตโฟน" (BANTAWAN)** ได้รับการวิจัย พัฒนา และประเมินผลสำเร็จลุล่วงตามวัตถุประสงค์ที่กำหนดไว้ทุกประการ โดยสามารถสรุปผลสัมฤทธิ์หลักได้ดังนี้:

1. **สถาปัตยกรรมแบบ Offline-First ที่สมบูรณ์:** ระบบสามารถปฏิบัติการได้โดยอัตโนมัติเมื่อปราศจากการเชื่อมต่ออินเทอร์เน็ต ผ่านการประสานงานของฐานข้อมูลภายในเครื่อง SQLite V6, SharedPreferences และการจัดการแคชแผ่นภาพแผนที่ (`OfflineFallbackTileProvider`)
2. **ระบบสื่อสารไร้สายเฉพาะกิจ (P2P Mesh Networking):** ประสบความสำเร็จในการประยุกต์ใช้ Google Nearby Connections API เพื่อสร้างโครงข่าย P2P Cluster ผ่านคลื่นวิทยุ Bluetooth Low Energy และ Wi-Fi Direct โดยมีอัตราความสำเร็จในการส่งข้อความในระยะสายตาเฉลี่ย **ร้อยละ 94.5** และความหน่วงเวลาเฉลี่ย **1.42 วินาที** พร้อมกลไกการส่งต่อหลายทอด (Multi-hop Relay) และระบบคนเดินสาร (Data Mule) เพื่อข้ามผ่านพื้นที่อับสัญญาณ
3. **ความมั่นคงปลอดภัยขั้นสูง (End-to-End Encryption):** พัฒนาระบบเข้ารหัสลับระดับแอปพลิเคชันอย่างครบวงจรด้วย X25519 ECDH, HKDF-SHA256, AES-256-CTR, HMAC-SHA256 AEAD, ระบบป้องกัน Replay Attack ด้วย LRU Nonce Cache และการเก็บรักษากุญแจใน Android Keystore
4. **ระบบแผนที่และการค้นหาสถานพยาบาลแบบไฮบริด:** สามารถสืบค้นพิกัดสถานพยาบาลผ่าน Overpass API และ Longdo Map API ในโหมดออนไลน์ และสลับสู่การกรองด้วยสูตรตรีโกณมิติทรงกลม Haversine บนแผนที่ออฟไลน์ได้อย่างไร้รอยต่อ
5. **ชุดเครื่องมือเอาชีวิตรอดและปฐมพยาบาล:** รวบรวมฟังก์ชันการส่งสัญญาณ SOS กดค้าง 3 วินาที, ไซเรนความถี่สูง, สัญญาณไฟกะพริบรหัสมอร์ส, เข็มทิศเรดาร์, และคู่มือปฐมพยาบาลประกอบเสียงสังเคราะห์ภาษาไทย (TTS) ช่วยลดภาระทางปัญญาของผู้ประสบภัยในภาวะวิกฤต

## 5.2 ปัญหา อุปสรรค และข้อจำกัดของระบบ (Problems, Challenges & Limitations)

จากการวิจัยและทดลองจริง พบข้อจำกัดเชิงเทคนิคและสภาพแวดล้อมดังนี้:
1. **ข้อจำกัดด้านสิ่งกีดขวางทางกายภาพ:** สัญญาณบลูทูธและ Wi-Fi Direct ในย่านความถี่ 2.4 GHz ถูกลดทอนลงอย่างรวดเร็วเมื่อผ่านโครงสร้างคอนกรีต ผนังอาคาร หรือแนวป่าหนาทึบ ส่งผลให้อัตราความสำเร็จในการส่งข้อมูลลดลงเมื่ออยู่นอกระยะสายตา (Non-Line-of-Sight)
2. **ความแตกต่างของฮาร์ดแวร์สมาร์ตโฟนแต่ละรุ่น (Hardware Fragmentation):** ความไวของเสาอากาศบลูทูธและกำลังส่งคลื่นวิทยุในสมาร์ตโฟนระบบ Android แต่ละแบรนด์มีความแตกต่างกันอย่างมีนัยสำคัญ ส่งผลให้ระยะการค้นพบโหนดข้างเคียงมีความแปรปรวน
3. **ข้อจำกัดด้านแพลตฟอร์ม (Cross-Platform Constraint):** ไลบรารี Google Nearby Connections ทำงานบนฐานของ Google Play Services ของระบบ Android เป็นหลัก ทำให้การเชื่อมต่อเครือข่ายเมชไร้เน็ตแบบไร้รอยต่อระหว่างอุปกรณ์ Android กับ iOS ยังมีข้อจำกัดด้านข้อกำหนดความปลอดภัยของ Apple
4. **ข้อจำกัดด้านพลังงานแบตเตอรี่:** การเปิดให้ชิปเซ็ตบลูทูธทำหน้าที่ทั้งการ Advertising และ Scanning อย่างต่อเนื่อง ควบคู่กับการเปิด GPS ส่งผลให้อัตราการสิ้นเปลืองแบตเตอรี่สูงขึ้น แม้จะมีระบบ Ultra Power-Saving ช่วยบรรเทาก็ตาม

## 5.3 ข้อเสนอแนะและแนวทางการพัฒนาต่อยอดในอนาคต (Recommendations & Future Work)

เพื่อยกระดับขีดความสามารถของระบบ BANTAWAN ให้มีความพร้อมในระดับอุตสาหกรรมและการบรรเทาสาธารณภัยระดับชาติ คณะผู้พัฒนาขอเสนอแนะแนวทางพัฒนาต่อยอดดังนี้:

1. **การพัฒนาระบบคัดเลือกเส้นทางส่งต่อข้อมูลอัจฉริยะ (Multi-hop Routing Optimization):** นำอัลกอริทึมการประเมินคุณภาพช่องสัญญาณ (Link Quality Estimation) เช่น RSSI (Received Signal Strength Indicator) และระดับพลังงานแบตเตอรี่ของโหนดกลางทาง มาเป็นค่าน้ำหนักในการเลือกโหนดรีเลย์ เพื่อลดภาระของโหนดที่มีพลังงานต่ำ
2. **การติดตั้งโหนดกระจายสัญญาณคงที่ (Static Mesh Beacons / LoRa Bridge):** การติดตั้งอุปกรณ์บีคอนขนาดเล็กที่ใช้พลังงานแสงอาทิตย์หรือแบตเตอรี่อายุยืนยาว (เช่น ESP32 หรือโมดูล LoRa ความถี่ 920–925 MHz) ไว้ตามจุดเสี่ยงภัย เสาไฟ หรือจุดรวมพล จะช่วยเป็นแกนหลัก (Backbone) ในการส่งต่อสัญญาณฉุกเฉินได้ไกลหลายกิโลเมตร
3. **การพัฒนาระบบบริดจ์ข้ามแพลตฟอร์ม Android–iOS:** วิจัยและพัฒนา Custom BLE Mesh Engine ระดับล่างเพื่อทำหน้าที่เป็นสะพานเชื่อมต่อแพ็กเก็ตระหว่างอุปกรณ์ระบบ Android และ iOS ในสภาวะออฟไลน์โดยตรง
4. **การเชื่อมต่อกับระบบบัญชาการกู้ภัยส่วนกลาง (Central Incident Command System: ICS):** เมื่อโหนดคนเดินสารหรือเจ้าหน้าที่เดินทางถึงพื้นที่ที่มีสัญญาณอินเทอร์เน็ต ระบบควรมีเกตเวย์ซิงก์ข้อมูลพิกัดผู้ประสบภัยทั้งหมดขึ้นสู่ระบบสารสนเทศภูมิศาสตร์ของกรมป้องกันและบรรเทาสาธารณภัย (ปภ.) โดยอัตโนมัติ เพื่อสนับสนุนการวางแผนกู้ชีพอย่างเป็นเอกภาพ
